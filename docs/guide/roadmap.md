# План развития

HealthCraft развивается в 4 направлениях, и разделы ниже идут в порядке приоритета.

## Развитие методики оценки

- Состояние кода дополнят статические анализаторы для всех языков репозитория: сложность функций, доля дублирования, покрытие тестами из артефактов CI и результаты линтеров. Владелец увидит, какие файлы снижают оценку. Текущий состав категории описан в разделе [Состояние кода](method/metrics.md#code).
- HealthCraft научится различать в CI шаги с тестами, сборкой и проверками, и пайплайн, который проверяет каждое изменение, получит более высокую оценку. Как CI/CD оценивается сейчас, описано в разделе [CI/CD](method/metrics.md#cicd).
- Частота коммитов будет считаться по активным дням, чтобы [Активность](method/metrics.md#activity) точнее показывала, насколько ровно команда работает над проектом.
- В категории Задачи начнут учитываться закрытие с участием второго человека и ответы в закрытых задачах. Выше оценку получат проекты, где на задачи отвечают по существу; текущие правила – в разделе [Задачи](method/metrics.md#issues).
- Безопасность будет учитывать граф зависимостей из SCA AppSec: уязвимость в прямой зависимости и в транзитивной получат разный вес. Рекомендация назовет уязвимый пакет, прямую зависимость, через которую он попал в проект, и версию, до которой его обновить. Как считается категория сейчас, описано в разделе [Безопасность](method/metrics.md#security).
- HealthCraft научится распознавать вендорные зависимости, скопированные в репозиторий. Их уязвимости и устаревшие версии он покажет отдельно, а Состояние кода будет описывать собственный код проекта.
- Веса категорий и подметрик будут уточняться по накопленной истории оценок. Каждое уточнение выйдет новой версией модели оценки, а оценки пересчитаются из сохраненных фактов по правилам из раздела [Воспроизводимость и версии](method/scores.md#versii).

## AI-возможности

- Каждое число в AI-обзоре будет открывать факт анализа, из которого оно взято, так же как сейчас это делает плашка показателя у рекомендации. Как тексты модели привязаны к фактам сегодня, описано в разделе [Привязка к фактам и проверка](data/ai.md#proverka-faktami).
- AI-рекомендация будет предлагать готовое изменение, например предложение изменений с заготовкой файла, дополненной под репозиторий. Заготовки для документации уже есть в рекомендациях, они описаны в разделе [Заготовки файлов](method/recommendations.md#zagotovki).
- Руководитель получит 1 обзор по всем репозиториям организации: где риски и что исправить в первую очередь.
- Каждый репозиторий получит вид проекта – сайт, фреймворк, библиотека, приложение, бот – и тематику. Языковая модель определит их по описанию, README и структуре файлов. В рейтинге появятся флаги вида и фильтры по виду и тематике, а оценка для всех видов останется общей. Нынешние фильтры описаны в разделе [Поиск и фильтры](guide/rating.md#filtry).
- На карточке можно будет задать вопрос языковой модели и получить ответ со ссылками на факты.

## Интеграция с SourceCraft

SourceCraft получит встроенную оценку здоровья репозиториев, а команды – подсказки там, где они работают каждый день.

- Оценка появится на странице репозитория SourceCraft рядом с его описанием.
- Шаг CI «проверка здоровья» посчитает оценку в пайплайне SourceCraft, а порог оценки станет условием слияния предложения изменений.
- Рекомендация с заготовкой файла сама откроет предложение изменений в репозитории.
- О падении оценки или смене зоны владелец узнает из уведомления сразу после анализа.
- Руководитель увидит общую оценку организации и сможет сравнить команды между собой.
- Команда SourceCraft CLI покажет оценку в терминале, а MCP-сервер HealthCraft откроет агентам и SourceCraft Code Assistant оценку, факты и рекомендации.
- По персональному токену участника API будет отдавать полный Repo Health Score с CI/CD и Безопасностью. Нынешний публичный API описан на странице [Бейдж и публичный API](guide/badge-api.md).

## Масштабирование

- База и очередь переедут на сетевую СУБД, а обработчики анализов будут работать на нескольких машинах. Тогда каталог и число пользователей смогут расти без смены сервера; текущая схема описана в разделе [Масштабирование](ops/scaling.md#masshtabirovanie).
- Все процессы будут делить единые квоты запросов к SourceCraft, и нагрузка на платформу останется в заданных пределах при любом числе обработчиков. Действующие бюджеты перечислены в разделе [Бюджеты и повторы запросов](data/sources.md#byudzhety).
- Повторный анализ будет обрабатывать только новые коммиты, поэтому оценка станет обновляться быстрее, а клон и запросы займут меньше ресурсов.
