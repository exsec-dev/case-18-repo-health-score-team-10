# Как меняется оценка

Существенная проблема заметно снижает ту оценку, в которую входит ее категория, а исправление возвращает оценку назад. Отсутствие данных оценку не штрафует. Ниже это показано на выдуманном репозитории `my-team/backend`: все числа посчитаны моделью `4.4.0-hci` по [формуле](scores.md#formula).

## Исходное состояние {#ishodnoe}

У `my-team/backend`, например:

- 4 автора, 36 коммитов за 90 дней, последний – 3 дня назад, 8 предложений изменений за 90 дней и 3 релиза за год;
- README с разделами установки и сборки, лицензия и CONTRIBUTING, файла CODEOWNERS нет;
- 18 000 строк кода, 30 файлов тестов на 150 файлов кода, 24 пометки TODO и FIXME, 14 записей в корне;
- 12 открытых и 60 закрытых задач, медиана закрытия – 6 дней;
- CI с 95% успешных запусков, в AppSec 2 находки средней и 3 низкой важности.

| Категория | Балл | Вес в HealthCraft Index | Вес в Repo Health Score |
|---|---:|---:|---:|
| Документация | 74,8 | 23 | 15 |
| Активность | 76,8 | 23 | 15 |
| Задачи | 87,8 | 23 | 15 |
| Состояние кода | 85,1 | 31 | 20 |
| CI/CD | 90,9 | – | 15 |
| Безопасность | 79,2 | – | 20 |

HealthCraft Index: (74,8 × 23 + 76,8 × 23 + 87,8 × 23 + 85,1 × 31) / 100 = 81,4 → 81, зона «здоров». Repo Health Score по 6 категориям – 82,4 → 82.

## Проблемы {#problemy}

В каждой строке меняется только одна группа фактов, остальные – как в исходном состоянии.

| Сценарий | Что изменилось | Балл категории | HealthCraft Index | Repo Health Score |
|---|---|---|---:|---:|
| Утек критичный секрет | в AppSec открытая находка `SECRETS` с критичностью `CRITICAL` | Безопасность: 79,2 → 40 | 81 → 81 | 82 → 49 |
| Сломан CI | последний запуск завершился ошибкой, успешны 30% запусков | CI/CD: 90,9 → 60,1 | 81 → 81 | 82 → 78 |
| Нет документации | нет README, лицензии, CONTRIBUTING и CODEOWNERS | Документация: 74,8 → 0 | 81 → 64 | 82 → 71 |
| Проект заброшен | последний коммит – 900 дней назад, нет предложений изменений за 90 дней и релизов за год | Активность: 76,8 → 16,3 | 81 → 68 | 82 → 73 |
| Задачи не закрываются | 60 открытых, из них 45 без движения дольше 90 дней; закрыто 8; медиана закрытия – 120 дней; первый ответ – через 400 ч | Задачи: 87,8 → 18,4 | 81 → 65 | 82 → 72 |
| Плохое состояние кода | 540 пометок на 18 000 строк, 74% из них старше 180 дней; тестов нет; 60 записей в корне | Состояние кода: 85,1 → 25,3 | 81 → 63 | 82 → 70 |

Что видно из таблицы:

- Утечка секрета не меняет HealthCraft Index: данных AppSec в нем нет. Repo Health Score по категориям был бы 74,6, но [потолок](scores.md#potolok) ограничивает его 49. Открытая находка `critical` вдобавок ограничивает балл Безопасности 40.
- Сломанный CI снижает Repo Health Score на 4,6: у CI/CD вес 15 из 100, а настроенный `ci.yaml` засчитывается и при красных запусках.
- Проблемы в 4 открытых категориях снижают HealthCraft Index на 13-18 баллов и переводят его из зоны «здоров» в «требует внимания». В Repo Health Score у этих категорий меньший вес, поэтому он падает на 9-12 баллов.

## Исправления {#ispravleniya}

Одинаковые факты дают одинаковую оценку. Когда проблему исправили и новый анализ собрал прежние факты, оценка возвращается к прежнему числу.

| Исправление | HealthCraft Index | Repo Health Score |
|---|---:|---:|
| Секрет заменен и удален из кода, находка закрыта | 81 | 49 → 82 |
| CI снова проходит, успешны 95% запусков | 81 | 78 → 82 |
| Добавлен файл лицензии – рекомендация №1, «+5,8 к HealthCraft Index» | 64 → 70 | 71 → 75 |
| Возвращены README, лицензия и CONTRIBUTING, как в исходном состоянии | 64 → 81 | 71 → 82 |
| Добавлены тесты в 10% файлов кода – рекомендация №1, «+3,7 к HealthCraft Index» | 63 → 67 | 70 → 73 |
| Задачи разобраны: снова 12 открытых и 60 закрытых | 65 → 81 | 72 → 82 |
| Работа над проектом возобновлена | 68 → 81 | 73 → 82 |

После лицензии индекс равен 69,98, это 70 после округления – зона «здоров». Поэтому режим «По шагам» для репозитория без документации предлагает 1 шаг. Как строятся шаги – в разделе [Режим «По шагам»](recommendations.md#po-shagam).

## Нет данных {#net-dannyh}

Категория без данных не получает 0: она выпадает из формулы, а ее вес делится между остальными.

| Ситуация | Что происходит | HealthCraft Index | Repo Health Score |
|---|---|---:|---:|
| API задач не ответил | Задачи – «нет данных», покрытие индекса 50 / 65 = 0,77 | 81 → 80 | 82 → 81 |
| Запуски CI не видны | CI/CD – «нет данных» | 81 → 81 | 82 → 81 |
| Нет данных AppSec | Безопасность – «нет данных» | 81 → 81 | 82 → 83 |
| Данные есть только по Документации | покрытие индекса 15 / 65 = 0,23, ниже 0,4 | оценки нет | оценки нет |

Без категории оценка – среднее оставшихся, поэтому она может сдвинуться в обе стороны. Задачи были лучшей категорией, и без них индекс снизился на 1,9. Безопасность была ниже среднего, и без нее Repo Health Score вырос на 0,8. Если бы «нет данных» считалось нулем, индекс без Задач был бы 61.

Подтвержденное отсутствие – другое дело. Если в трекере 0 открытых и 0 закрытых задач, это факт «трекер не ведется»: Задачи получают 6, индекс – 63. Подробнее – на странице [Когда данных нет](no-data.md).
