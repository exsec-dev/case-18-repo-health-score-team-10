# Два показателя и формула

HealthCraft считает 2 оценки от 0 до 100 по одной формуле: взвешенное среднее баллов категорий, у которых есть данные. Показатели различаются набором категорий и весами. Страница описывает модель оценки `4.4.0-hci`.

## HealthCraft Index и Repo Health Score {#dva-pokazatelya}

| Показатель | Категории | Кому виден |
|---|---|---|
| **HealthCraft Index** | Документация, Активность, Задачи, Состояние кода | всем: рейтинг, карточка, отчет, бейдж, публичный API |
| **Repo Health Score** | те же 4 категории, CI/CD и Безопасность | участнику репозитория, если его токену доступны и CI/CD, и Безопасность: карточка и отчет |

## Почему рейтинг по HealthCraft Index {#pochemu-index}

Результаты запусков CI и находки AppSec SourceCraft отдает только участникам репозитория. У большинства открытых репозиториев этих данных для HealthCraft нет, и Repo Health Score считался бы у разных репозиториев по разным наборам категорий. HealthCraft Index у всех считается по одним и тем же 4 категориям, поэтому места в рейтинге сравнимы.

Популярность в оценку не входит: реакции и ответвления не участвуют в формуле, по реакциям рейтинг можно только отсортировать. Как индекс определяет место и лигу – в разделе [Место и лига](../guide/rating.md#mesto-liga).

## Веса категорий {#vesa}

| Категория | Repo Health Score | HealthCraft Index |
|---|---:|---:|
| Документация | 15 | 23 |
| Активность | 15 | 23 |
| Задачи | 15 | 23 |
| Состояние кода | 20 | 31 |
| CI/CD | 15 | – |
| Безопасность | 20 | – |
| Сумма | 100 | 100 |

Больший вес – у категорий, которые описывают сам код: Состояние кода и Безопасность. Остальные категории весят одинаково – по 15.

Веса HealthCraft Index – те же веса 4 открытых категорий, пересчитанные на сумму 100 и округленные до целых. Вес 15 дает 15 / 65 × 100 = 23,08 → 23, вес 20 – 20 / 65 × 100 = 30,77 → 31. Так вес каждой категории читается как ее доля в процентах – в этом виде его показывает панель [[info:Как считается?]] в рейтинге. Из-за округления весов Repo Health Score без данных CI/CD и Безопасности может отличаться от HealthCraft Index на доли балла.

## Формула {#formula}

```text
оценка = Σ (балл категории × вес категории) / Σ (вес категории)
```

Здесь Σ – сумма, и обе суммы берутся только по категориям с данными. Балл категории – число от 0 до 100, вес – из таблицы выше. Словами: умножьте балл каждой категории с данными на ее вес, сложите произведения и разделите на сумму весов этих категорий.

Балл категории считается так же – по подметрикам, см. [Категории и метрики](metrics.md).

## Категория без данных {#bez-dannyh}

Категория без данных не получает 0: она выпадает из обеих сумм формулы. Ее вес делится между остальными категориями пропорционально их весам.

Например, у репозитория не удалось прочитать строки кода, и у категории Состояние кода нет данных. Баллы остальных категорий – 40, 55,5 и 20,4. Индекс считается по 3 категориям с весом 23, и каждая дает треть оценки: (40 + 55,5 + 20,4) × 23 / 69 = 38,63 → 39.

Причины «нет данных» – на странице [Когда данных нет](no-data.md).

## Порог данных {#porog-dannyh}

Покрытие – доля веса категорий с данными. Для обоих показателей его считают по весам Repo Health Score: для HealthCraft Index делят на 65, для Repo Health Score – на 100. Если покрытие ниже 0,4, оценка не ставится: на карточке – [[label-unknown:Оценки нет]], в рейтинге репозиторий попадает на вкладку [[Без оценки]].

- HealthCraft Index: порог проходят любые 2 категории (от 30 / 65 = 0,46), 1 категория – нет (не больше 20 / 65 = 0,31).
- Repo Health Score: нужны категории с суммой весов от 40, например 3 категории с весом 15 или 2 с весом 20.

В примере выше покрытие индекса – 45 / 65 = 0,69, на карточке в строке [[Покрытие]] – 69%.

## Репозиторий без кода {#bez-koda}

Обе оценки равны 0 при любом покрытии, если в репозитории:

- нет ни одного коммита;
- нет ни одного файла;
- только файлы, которые не считаются кодом: документы, лицензии, картинки, архивы;
- все файлы кода пустые.

Категория Состояние кода получает 0 с названной причиной. Отсутствие кода – подтвержденный факт о репозитории, поэтому правило про «нет данных» здесь не действует.

Если строки кода не удалось прочитать (файл больше лимита, не текстовый, чтение прервалось), это «нет данных», а не «кода нет».

## Потолок при утекшем секрете {#potolok}

Если AppSec нашел открытую находку типа `SECRETS` с критичностью `CRITICAL`, Repo Health Score не выше 49. Открытая – в статусе `OPEN`, `TRIAGE_IN_PROGRESS`, `TRIAGED_TP` или `FIX_IN_PROGRESS`. Потолок 49 лежит внутри зоны «требует внимания»: с утекшим секретом репозиторий не бывает «здоров». HealthCraft Index потолок не затрагивает, в нем нет данных AppSec. Карточка при потолке пишет, сколько дали бы категории без него.

## Зоны и округление {#zony}

| Зона | Оценка |
|---|---|
| [[label-success:Здоров]] | 70-100 |
| [[label-warning:Требует внимания]] | 40-69 |
| [[label-danger:В зоне риска]] | 0-39 |

Формула работает с дробными баллами. Показанная оценка – целое число по правилам арифметического округления: 69,5 → 70. Перед округлением HealthCraft убирает погрешность двоичной арифметики: если в расчете вышло 39,49999999999999 вместо 39,5, оценка будет 40. Зону определяет округленное число. Одно и то же целое видно в рейтинге, на карточке, в отчете, в бейдже и в публичном API. Баллы категорий публичный API отдает без округления – по ним расчет можно повторить.

## Пример расчета {#primer}

Чтобы получить баллы категорий открытого репозитория, выполните:

```bash
curl https://health-craft.ru/api/v1/repos/<org>/<repo>
```

Например, для выдуманного репозитория `example/weather-bot` фрагмент ответа такой:

```json
{
  "healthcraftIndex": 70,
  "indexCoverage": 1,
  "categories": {
    "documentation": 58.5,
    "activity": 81.2,
    "issues": 44.6,
    "code": 88
  }
}
```

Данные есть по всем 4 категориям, поэтому покрытие – 65 / 65 = 1, сумма весов – 100.

| Категория | Балл | Вес | Балл × вес |
|---|---:|---:|---:|
| Документация | 58,5 | 23 | 1345,5 |
| Активность | 81,2 | 23 | 1867,6 |
| Задачи | 44,6 | 23 | 1025,8 |
| Состояние кода | 88 | 31 | 2728,0 |
| Сумма | | 100 | 6966,9 |

Оценка: 6966,9 / 100 = 69,67 → 70. После округления репозиторий попадает в зону «здоров», хотя точное значение меньше 70. Результат совпадает с `healthcraftIndex` в ответе.

На карточке вклады категорий округлены до десятых так, чтобы их сумма совпала с показанной оценкой: в этом примере вклады дают в сумме 70, а не 69,67.
