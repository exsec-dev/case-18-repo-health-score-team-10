# Показатели и формула расчета

HealthCraft считает 2 оценки от 0 до 100 по одной формуле – как взвешенное среднее баллов тех категорий, по которым есть данные. Показатели отличаются набором категорий и их весами. Все числа на странице относятся к модели оценки `4.5.0-hci`.

## HealthCraft Index и Repo Health Score {#dva-pokazatelya}

| Показатель | Категории | Кому виден |
|---|---|---|
| **HealthCraft Index** | Документация, Активность, Задачи, Состояние кода | всем: рейтинг, карточка, отчет, бейдж, публичный API |
| **Repo Health Score** | те же 4 категории, CI/CD и Безопасность | участнику репозитория, если его токену доступны и CI/CD, и Безопасность: карточка и отчет |

## Почему рейтинг по HealthCraft Index {#pochemu-index}

Результаты запусков CI и находки AppSec – закрытые данные репозитория, их видят его участники. Для большинства открытых репозиториев таких данных у HealthCraft нет, и Repo Health Score пришлось бы считать у разных репозиториев по разным наборам категорий. HealthCraft Index у всех считается по одним и тем же 4 категориям, поэтому места в рейтинге сравнимы.

Реакции и ответвления в формулу не входят – почему, объяснено на странице [Устойчивость оценки и защита от накрутки](robustness.md). Как по индексу определяются место и лига, описано в разделе [Место и лига](../guide/rating.md#mesto-liga).

## Веса категорий {#vesa}

| Категория | Repo Health Score | HealthCraft Index |
|---|---:|---:|
| Документация | 15 | 23 |
| Активность | 15 | 23 |
| Задачи | 15 | 23 |
| Состояние кода | 20 | 31 |
| CI/CD | 15 | – |
| Безопасность | 20 | – |
| Сумма | 100 | 100 |

У Безопасности и Состояния кода вес по 20: они описывают риски самого кода, которые достаются каждому, кто берет проект в работу или подключает его как зависимость. Документация, Активность, Задачи и CI/CD описывают процессы вокруг кода и весят по 15. Вес одной категории не превышает 20 из 100, а в HealthCraft Index – 31 из 100, так что проблема в одной категории заметно снижает оценку, но не определяет ее в одиночку. Критичные риски ограничивают оценку потолками – они описаны в разделе [Потолки Repo Health Score](#potolok) и в категории [Безопасность](metrics.md#security).

Веса HealthCraft Index получены из весов 4 открытых категорий: их пересчитали на сумму 100 и округлили до целых, например 15 / 65 × 100 = 23,08 → 23 и 20 / 65 × 100 = 30,77 → 31. Из-за округления Repo Health Score без данных CI/CD и Безопасности может отличаться от HealthCraft Index на доли балла.

## Формула {#formula}

```text
оценка = Σ (балл категории × вес категории) / Σ (вес категории)
```

Обе суммы берутся только по категориям, у которых есть данные. Балл категории – число от 0 до 100; как он складывается из подметрик, описано на странице [Категории и метрики](metrics.md).

## Категория без данных {#bez-dannyh}

Категория без данных не получает 0: она выпадает из обеих сумм формулы, а ее вес делится между остальными категориями пропорционально их весам.

Например, у Состояния кода нет данных, а остальные категории получили 40, 55,5 и 20,4. У всех трех вес 23, поэтому каждая дает треть оценки: (40 + 55,5 + 20,4) × 23 / 69 = 38,63 → 39.

Из-за чего у категории бывает «нет данных», рассказано на странице [Обработка отсутствующих данных](no-data.md).

## Порог данных {#porog-dannyh}

Полнота данных показывает, какая доля веса категорий получила данные. Для обоих показателей ее считают по весам Repo Health Score и делят на сумму весов показателя: 65 для HealthCraft Index и 100 для Repo Health Score. Если полнота данных ниже 0,4, оценка не ставится: на карточке появляется отметка [[label-unknown:Оценки нет]], а в рейтинге репозиторий попадает на вкладку [[Без оценки]].

Для HealthCraft Index порог проходят любые 2 категории – их полнота данных не меньше 30 / 65 = 0,46, а одной категории не хватает: у нее не больше 20 / 65 = 0,31. Для Repo Health Score нужны категории с суммой весов от 40, например 3 категории с весом 15 или 2 с весом 20.

В примере из предыдущего раздела полнота данных индекса равна 45 / 65 = 0,69, и на карточке в строке [[Полнота данных]] стоит 69%. Если вам виден Repo Health Score, на карточке вместо нее 2 строки: [[Полнота: индекс]] и [[Полнота: полная оценка]].

## Репозиторий без кода {#bez-koda}

Обе оценки равны 0 при любой полноте данных, если в репозитории:

- нет ни одного коммита;
- нет ни одного файла;
- только файлы, которые не считаются кодом: документы, лицензии, картинки, архивы, бинарные файлы;
- все файлы кода пустые.

Отсутствие кода – подтвержденный факт, поэтому Состояние кода получает 0, а карточка называет причину. Такой репозиторий остается в рейтинге с оценкой 0 и отметкой [[label-unknown:нет кода]], и его не спутать с проектом, у которого просто низкие баллы. Все такие репозитории отбирает фильтр [[Размер:]] со значением [[без кода]]. Бинарный файл не считается кодом, даже если у него расширение языка программирования. Иначе обстоит дело, если строки кода не удалось прочитать: файл оказался больше лимита или чтение прервалось. Тогда у категории «нет данных».

## Потолки Repo Health Score {#potolok}

Критичные риски безопасности ограничивают Repo Health Score сверху, как бы хорошо ни выглядели остальные категории:

| Что нашел AppSec | Repo Health Score |
|---|---:|
| Открытая находка типа `SECRETS` с критичностью `CRITICAL` – утекший секрет | не выше 49 |
| Открытая находка с критичностью `CRITICAL` любого вида, например уязвимость зависимости | не выше 69 |

Открытой считается находка в статусе `OPEN`, `TRIAGE_IN_PROGRESS`, `TRIAGED_TP` или `FIX_IN_PROGRESS`. Если действуют оба потолка, применяется меньший. Так репозиторий с утекшим секретом или открытой критичной уязвимостью не попадает в зону «здоров»: 69 – верхняя граница зоны «требует внимания». На HealthCraft Index потолки не влияют, потому что данных AppSec в нем нет. Когда потолок срабатывает, карточка показывает, сколько дали бы категории без него.

## Зоны и округление {#zony}

| Зона | Оценка |
|---|---|
| [[label-success:Здоров]] | 70-100 |
| [[label-warning:Требует внимания]] | 40-69 |
| [[label-danger:В зоне риска]] | 0-39 |

Оценка показывается целым числом, округленным по арифметическим правилам: 69,5 → 70. Зону определяет уже округленное число, и оно же стоит в рейтинге, на карточке, в отчете, в бейдже и в публичном API.

## Пример расчета {#primer}

Публичный API отдает баллы категорий без округления, поэтому расчет можно повторить. Чтобы получить баллы открытого репозитория, выполните:

```bash
curl https://health-craft.ru/api/v1/repos/<org>/<repo>
```

Например, для выдуманного `example/weather-bot` фрагмент ответа такой:

```json
{
  "healthcraftIndex": 70,
  "indexCoverage": 1,
  "categories": {
    "documentation": 58.5,
    "activity": 81.2,
    "issues": 44.6,
    "code": 88
  }
}
```

Данные есть по всем 4 категориям, поэтому полнота данных равна 65 / 65 = 1, а сумма весов – 100.

| Категория | Балл | Вес | Балл × вес |
|---|---:|---:|---:|
| Документация | 58,5 | 23 | 1345,5 |
| Активность | 81,2 | 23 | 1867,6 |
| Задачи | 44,6 | 23 | 1025,8 |
| Состояние кода | 88 | 31 | 2728,0 |
| Сумма | | 100 | 6966,9 |

Оценка равна 6966,9 / 100 = 69,67 → 70, это зона «здоров». Результат совпадает с полем `healthcraftIndex` в ответе.

## Воспроизводимость и версии {#versii}

Оценку считает код без случайности и без языковой модели, поэтому одинаковые факты на одну дату анализа всегда дают одну и ту же оценку. Вместе с каждой оценкой записана версия модели, то есть набора формул, весов и порогов. Когда модель меняется, HealthCraft пересчитывает историю по сохраненным фактам без новых анализов, и все точки [[История оценки]] остаются сравнимыми. Версию можно увидеть в панели [[Как считается?]] рейтинга, в разделе [[Реквизиты]] карточки, в отчете и в поле `modelVersion` публичного API.
