# Переменные окружения

Все настройки HealthCraft задаются переменными окружения, для запуска достаточно `SOURCECRAFT_TOKEN`. Ниже – переменные, которые меняют чаще всего. Полный список с пояснениями и значениями по умолчанию – в файле `.env.example` в корне репозитория.

## Где задаются

- Из исходников HealthCraft читает `.env` в текущем каталоге. Переменная окружения процесса важнее строки в файле.
- В контейнерах Docker Compose передает сервису файл `.env` из рабочего каталога `HC_DIR`. Не задавайте в нем `PROCESS_ROLE`, `PORT` и `SCAN_MIN_FREE_MB` – их задает `deploy/compose.yaml`, и `DATA_DIR` – его задает образ.

Как задавать значения:

- время – в миллисекундах: 5 мин – `300000`;
- число – целое больше 0; пустое значение, 0 и нечисловое значение означают значение по умолчанию, если в `.env.example` не сказано иное;
- переключатель – `true` или `false`, `1` или `0`.

## Минимум для запуска

```ini
SOURCECRAFT_TOKEN=<персональный токен SourceCraft>
```

Без токена API SourceCraft отвечает 401: обход каталога и анализ не идут, а `/api/health` сообщает об этом в поле `reasons`.

## Вход через Яндекс ID

| Переменная | Что задает |
|---|---|
| `APP_SECRET` | ключ подписи сессий и шифрования токенов пользователей, не короче 32 символов; без него вход выключен |
| `YA_CLIENT_ID`, `YA_CLIENT_SECRET` | OAuth-приложение Яндекс ID; без них вход отвечает 503 |
| `YA_REDIRECT_URI` | адрес возврата после входа, как в OAuth-приложении; по умолчанию `http://localhost:8418/auth/ya/callback` |

Сгенерировать `APP_SECRET` можно командой `openssl rand -hex 32`.

{% note warning %}

Не меняйте `APP_SECRET` на работающем сервисе. Со старым ключом пропадут все сессии, а сохраненные персональные токены пользователей нельзя будет расшифровать: пользователям придется войти и сохранить токен заново.

{% endnote %}

## AI-обзор и проверка оценки

| Переменная | По умолчанию | Что задает |
|---|---|---|
| `LLM_PROVIDER` | `yandex` | провайдер: `yandex` (YandexGPT) или `zai` (резервный) |
| `MAIN_MODEL` | `yandexgpt` | модель; для `zai` по умолчанию `glm-5.3` |
| `YAGPT_API_KEY`, `YAGPT_FOLDER_ID` | – | API-ключ сервисного аккаунта и ID каталога Yandex Cloud |
| `ZAI_API_KEY` | – | ключ резервного провайдера |
| `AI_OVERVIEW_PER_HOUR`, `AI_OVERVIEW_PER_DAY` | 2, 6 | AI-обзоров на человека в час и в сутки |
| `AI_CHECK_PER_HOUR`, `AI_CHECK_PER_DAY` | 5, 20 | проверок оценки на человека в час и в сутки |
| `AI_UNLOCK_PASSWORD` | – | пароль снятия личных лимитов, не короче 20 символов; нужен `APP_SECRET` |
| `AI_TOP_AUTO` | `0` | `1` – готовить обзор и проверку для топа рейтинга после нового анализа |

Без ключа модели AI-обзор недоступен, остальные функции работают.

## Сервер

| Переменная | По умолчанию | Что задает |
|---|---|---|
| `PORT` | 8418 | порт HTTP |
| `DATA_DIR` | `data` | каталог базы SQLite |
| `PROCESS_ROLE` | `all` | роль процесса: `all`, `web` или `rating`, см. [Архитектура](architecture.md) |
| `PUBLIC_BASE_URL` | адрес из `YA_REDIRECT_URI` | публичный адрес сервиса для кода бейджа |

## Обход каталога

| Переменная | По умолчанию | Что задает |
|---|---|---|
| `SCHEDULER_START_DELAY_MS` | 300000 (5 мин) | задержка первого обхода после старта |
| `SCHEDULER_CATALOG_INTERVAL_MS` | 3600000 (1 ч) | сверка каталога: новые и удаленные репозитории |
| `SCHEDULER_INTERVAL_MS` | 86400000 (24 ч) | повторный анализ изменившихся репозиториев |
| `SCHEDULER_FULL_RESCAN` | `false` | `true` – анализировать заново все репозитории, а не только изменившиеся |

## Бюджеты анализа

| Переменная | По умолчанию | Что задает |
|---|---|---|
| `SCAN_CLONE_TIMEOUT_MS` | 1200000 (20 мин) | предел времени клона |
| `SCAN_CLONE_MAX_BYTES` | 1610612736 (1,5 ГиБ) | предел размера клона |
| `SCAN_DEGRADE_ENABLED` | `true` | повтор клона с историей за 13 месяцев, если полный клон не уложился |
| `SCAN_MIN_FREE_MB` | не проверяется | свободное место перед клоном; меньше – клон ждет |
| `SCAN_BUDGET` | 1000 | запросов к REST API SourceCraft на 1 анализ |

## Очередь и лимиты пользователей

| Переменная | По умолчанию | Что задает |
|---|---|---|
| `QUEUE_USER_SCAN_SLOTS` | 2 | параллельных анализов пользователей в процессе, от 1 до 8 |
| `QUEUE_USER_SCANS_PER_HOUR` | 10 | запусков анализа на пользователя в час |
| `QUEUE_USER_ACTIVE_MAX` | 2 | одновременных запусков на пользователя |
| `QUEUE_MAX_ATTEMPTS` | 3 | попыток заявки до отказа |
| `SCHEDULER_LEASE_MS` | 600000 (10 мин) | через сколько заявка остановившегося процесса возвращается в очередь |

## Адреса внешних сервисов

`SOURCECRAFT_API_BASE`, `APPSEC_API_BASE`, `SOURCECRAFT_GIT_BASE`, `YA_OAUTH_BASE` и `YA_LOGIN_BASE` менять не нужно: в них тесты подставляют локальные заглушки.

## Запуск в контейнерах

Эти переменные читает `deploy/compose.yaml`, а не сервис. В `.env.example` они собраны в блоке «Стенд в контейнерах».

| Переменная | По умолчанию | Что задает |
|---|---|---|
| `SITE_ADDRESS` | не задан – только HTTP | домены для HTTPS через запятую; сертификат прокси выпускает сам |
| `CANONICAL_HOST` | – | основной домен: остальные адреса переадресуются на него |
| `STAND_IP` | – | IP машины: запрос `http://IP` переадресуется на основной домен; только вместе с `CANONICAL_HOST` |
| `HC_DIR` | `/srv/healthcraft` | рабочий каталог: `.env`, `data/`, `tmp/` |
| `HTTP_PORT`, `HTTPS_PORT` | 80, 443 | порты прокси на машине |

После правки `.env` в контейнерах пересоздайте их командой `docker compose ... up -d` – см. раздел [Изменение настроек](deploy.md#izmenit-nastroyki).
