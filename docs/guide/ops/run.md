# Установка и запуск

HealthCraft запускается из исходников командой `bun start` или в контейнерах Docker Compose. Для запуска достаточно персонального токена SourceCraft: рейтинг, карточки, отчеты и публичный API работают без входа и AI. Команды на странице – для bash: Linux, macOS или WSL в Windows.

## Что нужно

| Для чего | Что |
|---|---|
| Запуск из исходников | [Bun](https://bun.sh) 1.4.2; git 2.31 или новее: более ранние версии не передают токен при клоне, поэтому анализ с персональным токеном не склонирует ни один репозиторий |
| Запуск в контейнерах | Docker с Compose v2 |
| Данные | персональный токен SourceCraft, [как выпустить токен](https://sourcecraft.dev/portal/docs/ru/sourcecraft/security/pat) |
| Вход и AI, по желанию | для входа – OAuth-приложение Яндекс ID и ключ `APP_SECRET`, для AI – ключ YandexGPT и каталог Yandex Cloud |

## Запуск из исходников {#iz-ishodnikov}

Чтобы запустить HealthCraft на своей машине:

1. Склонируйте репозиторий. Клон по SSH требует ключа, добавленного в SourceCraft.
   ```bash
   git clone ssh://ssh.sourcecraft.dev/lct-hackaton-2026/case-18-repo-health-score-team-10.git
   ```
2. Перейдите в каталог репозитория.
   ```bash
   cd case-18-repo-health-score-team-10
   ```
3. Установите зависимости точно по lock-файлу.
   ```bash
   bun install --frozen-lockfile
   ```
4. Скопируйте файл настроек.
   ```bash
   cp .env.example .env
   ```
5. Впишите токен в `.env`, в строку `SOURCECRAFT_TOKEN=`. Остальные настройки – на странице [Развертывание и настройка](deploy.md).
6. Запустите сервис.
   ```bash
   bun start
   ```
7. Проверьте, что сервис работает. В ответе должно быть `"ok":true`.
   ```bash
   curl http://localhost:8418/api/health
   ```

Интерфейс откроется по адресу `http://localhost:8418`. База SQLite создается сама в каталоге `data/`.

Сразу после старта рейтинг пуст. Первый обход каталога SourceCraft начинается через 5 минут: HealthCraft ставит в очередь все открытые репозитории, начиная с тех, у кого больше реакций, и рейтинг наполняется по мере завершения анализов. Как устроено расписание, описано на странице [Периодический анализ и масштабирование](scaling.md).

## Анализ репозитория

Чтобы не ждать обхода каталога, проанализируйте репозиторий сразу, без очереди:

```bash
bun scripts/scan.ts <org>/<repo>
```

Небольшой репозиторий анализируется за несколько секунд. Команда печатает число фактов и статус:

| Статус | Что значит |
|---|---|
| `ok` | получены все факты |
| `partial` | часть фактов – «нет данных»; оценка считается по остальным |
| `bad` | анализ не удался, команда завершается с кодом 1 |

Для чужого репозитория `partial` – нормальный результат. Данные CI и AppSec – закрытые данные репозитория, их видят только его участники, а HealthCraft Index от них не зависит. Результат смотрите на карточке `http://localhost:8418/repo/<org>/<repo>` или через API:

```bash
curl http://localhost:8418/api/v1/repos/<org>/<repo>
```

## Запуск в контейнерах {#konteynery}

Файл `deploy/compose.yaml` поднимает 3 контейнера: `web` с сайтом и API, `rating` для обхода каталога и анализа рейтинга и `caddy` – прокси с HTTPS. Роли процессов подробно описаны на странице [Архитектура](architecture.md).

Чтобы запустить контейнеры локально:

1. Создайте рабочий каталог `.stand` для настроек, базы и временных клонов.
   ```bash
   mkdir -p .stand
   ```
2. Скопируйте в него файл настроек.
   ```bash
   cp .env.example .stand/.env
   ```
3. Впишите токен в `.stand/.env`, в строку `SOURCECRAFT_TOKEN=`.
4. Допишите в файл путь к рабочему каталогу.
   ```bash
   echo "HC_DIR=$PWD/.stand" >> .stand/.env
   ```
5. Соберите образ и запустите контейнеры. `HTTP_PORT` – порт прокси на машине, по умолчанию 80.
   ```bash
   HTTP_PORT=8080 docker compose --env-file .stand/.env -f deploy/compose.yaml up -d --build
   ```
6. Через несколько секунд проверьте состояние. В ответе должно быть `"ok":true`.
   ```bash
   curl http://localhost:8080/api/health
   ```

Без `SITE_ADDRESS` прокси работает только по HTTP. Если порт 443 занят, добавьте `HTTPS_PORT=8443` рядом с `HTTP_PORT`. Чтобы остановить контейнеры, выполните:

```bash
docker compose --env-file .stand/.env -f deploy/compose.yaml down
```

## Проверки

Те же команды CI выполняет при каждом push и в каждом предложении изменений. Чтобы проверить типы, выполните:

```bash
bun run tsc
```

Чтобы запустить тесты, выполните:

```bash
bun test --timeout 30000
```

Внешние сервисы тестам не нужны: SourceCraft, Яндекс ID и языковую модель заменяют локальные заглушки. Тестам нужны git, символьные ссылки и команда `setsid`, поэтому запускайте их в Linux или WSL. В macOS команды `setsid` может не быть. В контейнере `oven/bun:1.4.2` git нет: установите его перед тестами, как это делают `Dockerfile` и CI.

## Как получить те же результаты, что на health-craft.ru {#te-zhe-rezultaty}

Одинаковые факты, дата анализа и версия модели дают одинаковую оценку. Чтобы сверить свою установку со стендом:

1. Сравните поле `modelVersion` в ответах `http://localhost:8418/api/meta` и `https://health-craft.ru/api/meta`.
2. Проанализируйте у себя репозиторий из рейтинга командой `bun scripts/scan.ts <org>/<repo>`.
3. Запросите `/api/v1/repos/<org>/<repo>` у себя и на `https://health-craft.ru`.
4. Сравните `healthcraftIndex` и `categories`.

Если `headSha` есть в обоих ответах, оценки совпадут при одинаковом `headSha` и близком времени `scannedAt`. Задачи и предложения изменений меняются и без коммитов, а часть баллов, например активность, считается от даты анализа, поэтому сравнивайте анализы одного коммита, сделанные в один день. Правила расчета описаны на странице [Показатели и формула расчета](../method/scores.md).

Чтобы пересчитать оценку последнего анализа без сети, по уже сохраненным фактам, выполните:

```bash
bun scripts/score.ts <org>/<repo>
```

Команда считает текущей моделью оценки, записывает результат в базу и печатает баллы категорий и первые рекомендации. Сроки, например свежесть коммитов, она отсчитывает от момента запуска.

Отчет Markdown с публичной оценкой из той же базы собирает команда:

```bash
bun scripts/report.ts <org>/<repo> > report.md
```

В приложении отчета «Расчет оценки и исходные данные» – баллы, веса и факты, по которым расчет можно повторить вручную.

Как оценка ведет себя на контрольных наборах фактов, проверяют тесты:

```bash
bun test tests/score-mutations.test.ts
```
