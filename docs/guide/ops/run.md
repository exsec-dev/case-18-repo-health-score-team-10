# Сборка и запуск

HealthCraft запускается из исходников одной командой `bun start` или в контейнерах через Docker Compose. Для запуска достаточно персонального токена SourceCraft: рейтинг, карточки, отчеты и публичный API работают без входа и AI.

Команды на странице – для bash: Linux, macOS или WSL в Windows.

## Что нужно

| Для чего | Что |
|---|---|
| Запуск из исходников | [Bun](https://bun.sh) 1.4.2, git 2.31 или новее |
| Запуск в контейнерах | Docker с Compose v2 |
| Данные | персональный токен SourceCraft, [как выпустить токен](https://sourcecraft.dev/portal/docs/ru/sourcecraft/security/pat) |
| Вход и AI, по желанию | OAuth-приложение Яндекс ID, ключ YandexGPT и каталог Yandex Cloud |

Git нужен версии 2.31 или новее: более ранние версии не передают токен при клоне, и приватный репозиторий не склонируется.

## Запуск из исходников {#iz-ishodnikov}

Чтобы запустить HealthCraft на своей машине:

1. Склонируйте репозиторий. Клон по SSH требует ключа, добавленного в SourceCraft.
   ```bash
   git clone ssh://ssh.sourcecraft.dev/lct-hackaton-2026/case-18-repo-health-score-team-10.git
   ```
2. Перейдите в каталог репозитория.
   ```bash
   cd case-18-repo-health-score-team-10
   ```
3. Установите зависимости точно по lock-файлу.
   ```bash
   bun install --frozen-lockfile
   ```
4. Скопируйте файл настроек.
   ```bash
   cp .env.example .env
   ```
5. Откройте `.env` и впишите токен в строку `SOURCECRAFT_TOKEN=`. Остальные настройки – на странице [Переменные окружения](env.md).
6. Запустите сервис.
   ```bash
   bun start
   ```
7. Проверьте, что сервис работает. В ответе должно быть `"ok": true`.
   ```bash
   curl http://localhost:8418/api/health
   ```

Интерфейс откроется по адресу `http://localhost:8418`. База SQLite создается сама в каталоге `data/`. По умолчанию интерфейс собирается в режиме разработки: правки кода интерфейса подхватываются без перезапуска сервиса. Команда `NODE_ENV=production bun start` запускает минифицированную сборку.

## Что происходит после старта

Рейтинг сначала пуст. Первый обход каталога SourceCraft начинается через 5 минут после старта. HealthCraft ставит в очередь анализ всех открытых репозиториев, начиная с репозиториев с наибольшим числом реакций. Рейтинг наполняется по мере завершения анализов. Как устроено расписание – на странице [Периодический анализ и масштабирование](scaling.md).

## Анализ 1 репозитория

Чтобы не ждать обхода каталога, проанализируйте репозиторий сразу:

```bash
bun scripts/scan.ts <org>/<repo>
```

Команда запускает анализ без очереди и печатает статус и число фактов. Небольшой репозиторий анализируется за несколько секунд.

| Статус | Что значит |
|---|---|
| `ok` | получены все факты |
| `partial` | часть фактов – «нет данных»; оценка считается по остальным |
| `bad` | анализ не удался, команда завершается с кодом 1 |

Для чужого репозитория статус `partial` – нормальный результат: данные CI и AppSec SourceCraft отдает только участникам репозитория. HealthCraft Index от этих данных не зависит.

После анализа откройте карточку `http://localhost:8418/repo/<org>/<repo>` или запросите оценку через публичный API:

```bash
curl http://localhost:8418/api/v1/repos/<org>/<repo>
```

## Запуск в контейнерах {#konteynery}

Файл `deploy/compose.yaml` поднимает 3 контейнера. `web` – сайт и API, `rating` – обход каталога и анализ рейтинга, оба из общего образа HealthCraft. `caddy` – прокси с HTTPS. Устройство процессов – на странице [Архитектура](architecture.md).

Чтобы запустить контейнеры локально:

1. Создайте рабочий каталог `.stand`. В нем будут настройки, база и временные клоны.
   ```bash
   mkdir -p .stand
   ```
2. Скопируйте в него файл настроек.
   ```bash
   cp .env.example .stand/.env
   ```
3. Впишите токен в `.stand/.env`, в строку `SOURCECRAFT_TOKEN=`.
4. Допишите в файл путь к рабочему каталогу.
   ```bash
   echo "HC_DIR=$PWD/.stand" >> .stand/.env
   ```
5. Соберите образ и запустите контейнеры. `HTTP_PORT` задает порт прокси на машине, по умолчанию 80.
   ```bash
   HTTP_PORT=8080 docker compose --env-file .stand/.env -f deploy/compose.yaml up -d --build
   ```
6. Через несколько секунд проверьте состояние. В ответе должно быть `"ok": true`.
   ```bash
   curl http://localhost:8080/api/health
   ```

Без `SITE_ADDRESS` прокси работает только по HTTP. Если на машине занят порт 443, добавьте `HTTPS_PORT=8443` перед `docker compose`, рядом с `HTTP_PORT`. Остановить контейнеры:

```bash
docker compose --env-file .stand/.env -f deploy/compose.yaml down
```

## Проверки

Эти же команды выполняет CI при каждом push и каждом предложении изменений. Проверка типов:

```bash
bun run tsc
```

Тесты:

```bash
bun test --timeout 30000
```

Тесты создают временные базы и не обращаются к внешним сервисам: SourceCraft, Яндекс ID и языковую модель заменяют локальные заглушки. Тесты рассчитаны на Linux и macOS. В Windows часть тестов падает из-за символьных ссылок и команды `setsid` – запускайте их в WSL или в контейнере `oven/bun:1.4.2`.

## Как получить те же результаты, что на health-craft.ru {#te-zhe-rezultaty}

Оценку считает код: одинаковые факты, дата анализа и версия модели дают одинаковую оценку. Чтобы сверить свою установку со стендом:

1. Сравните версию модели: поле `modelVersion` в ответах `http://localhost:8418/api/meta` и `https://health-craft.ru/api/meta` должно совпадать.
2. Проанализируйте у себя репозиторий из рейтинга командой `bun scripts/scan.ts <org>/<repo>`.
3. Запросите `/api/v1/repos/<org>/<repo>` у себя и на `https://health-craft.ru`.
4. Сравните `healthcraftIndex` и `categories`. Они совпадают, если у анализов один `headSha` и близкое время `scannedAt`.

Оценки меняются вместе с репозиториями. Новый коммит меняет `headSha`. Задачи и предложения изменений меняются и без коммитов. Часть баллов, например активность, считается от даты анализа. Поэтому сравнивайте анализы одного коммита, сделанные в один день. Источники фактов те же, что у стенда, – см. [Источники данных](../data/sources.md). Как версия модели влияет на историю оценок – на странице [Версии модели и пересчет](../method/versions.md).
