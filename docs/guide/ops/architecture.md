# Архитектура

HealthCraft – один сервис на Bun и TypeScript, который работает в 2 процессах с общей базой SQLite. Процесс `web` обслуживает сайт и заявки пользователей, процесс `rating` обходит каталог SourceCraft и обновляет рейтинг. Перед ними стоит прокси Caddy с HTTPS.

## Схема

```text
                    браузер, README с бейджем
                               |
                   caddy: HTTPS, заголовки защиты
                               |
    +--------------------------+     +---------------------------------+
    | web                      |     | rating                          |
    | сайт и API, вход Я ID,   |     | обход каталога, плановые        |
    | анализы по заявкам,      |     | анализы, пересчет оценок,       |
    | AI-обзоры и проверки     |     | AI для топа рейтинга            |
    +------------+-------------+     +----------------+----------------+
                 |                                    |
                 +------> SQLite (WAL): факты, <------+
                          оценки, очередь заявок

  внешние сервисы: SourceCraft REST API, AppSec API, git-клоны
                   (временный каталог), Яндекс ID, YandexGPT
```

## Компоненты и роли процессов {#roli}

Роль процесса задает переменная `PROCESS_ROLE`, а образ и код у всех ролей общие.

| Компонент | Что делает |
|---|---|
| `caddy` | HTTPS с сертификатом Let's Encrypt, заголовки защиты, адрес клиента для лимитов. Единственный компонент с портами наружу: 80 и 443 |
| роль `web` | сайт и API, вход через Яндекс ID, циклы пользовательских заявок: анализы, AI-обзоры и проверки активности |
| роль `rating` | планировщик сверки каталога, циклы плановых анализов, суточный снимок мест рейтинга, пересчет оценок после смены модели, AI-тексты для топа рейтинга при `AI_TOP_AUTO=1` |
| роль `all` | все в одном процессе. Значение по умолчанию, для разработки |
| SQLite в режиме WAL | факты, оценки, рекомендации, очередь заявок, пользователи, зашифрованные токены, AI-тексты |
| Временный каталог | клоны репозиториев на время анализа, у каждого процесса свой |

HealthCraft можно развернуть в своей инфраструктуре почти как есть. Все роли запускаются из 1 образа, а роль процесса, бюджеты, лимиты и адреса API SourceCraft, AppSec и git задаются переменными окружения. Данные хранятся в базе SQLite на диске, отдельный сервер базы данных не нужен. Порядок развертывания описан на странице [Развертывание и настройка](deploy.md).

В контейнерах процесс `rating` стартует после того, как `web` прошел проверку здоровья, и получает меньшую долю процессора, поэтому плановая волна анализов не замедляет сайт. Раз в час оба процесса выполняют обслуживание: закрывают зависшие анализы, удаляют старые заявки и забытые клоны. Какие данные HealthCraft берет из внешних сервисов, описано на странице [Источники данных и приватность](../data/sources.md).

## Путь данных

1. Заявка на анализ попадает в очередь: пользователь нажал [[Обновить анализ]] или планировщик нашел новый либо изменившийся репозиторий.
2. Свободный цикл процесса берет заявку.
3. Анализ клонирует репозиторий и запрашивает REST API, а с персональным токеном автора заявки – еще и AppSec API.
4. Факты записываются в базу, клон удаляется.
5. Код считает оценки и рекомендации и записывает их вместе со статусом анализа одной транзакцией.
6. Карточка, рейтинг, отчеты и публичный API читают сохраненные данные.

AI-обзор идет отдельной заявкой: он работает с фактами последнего завершенного анализа и оценку не меняет.

## Очередь заявок {#ochered}

Заявки хранятся в таблице `jobs` той же базы. Они делятся на 2 полосы, пользовательскую и рейтинга, и на 3 рода – анализ, AI-обзор и проверку оценки. У каждой пары «полоса × род» свои циклы-исполнители:

| Цикл | Сколько параллельно | Переменная |
|---|---:|---|
| Анализы пользователей | 2 (от 1 до 8) | `QUEUE_USER_SCAN_SLOTS` |
| AI-обзоры пользователей | 2 (от 1 до 8) | `QUEUE_USER_AI_SLOTS` |
| Проверки оценки | 1 на полосу | – |
| Плановые анализы и AI для топа | 1 на род | – |

Цикл забирает заявку одной командой `UPDATE` с арендой на 10 мин (`SCHEDULER_LEASE_MS`) и продлевает ее, пока работает. При штатной остановке процесс возвращает свои заявки в очередь, не тратя попытку. Если процесс упал, аренда истекает и заявку берет другой цикл, а после 3 попыток (`QUEUE_MAX_ATTEMPTS`) она завершается с причиной [[превышено число попыток]].

В пользовательской полосе заявки разных людей идут по кругу: вторая заявка того же человека ждет чужие, но свободный цикл не простаивает. Репозиторий, анализ которого уже шел дольше 5 мин (`QUEUE_HEAVY_SCAN_MS`), берет только первый цикл, остальные в это время обслуживают небольшие репозитории.

## Стек

- Bun 1.4.2 и TypeScript в строгом режиме;
- SQLite через `bun:sqlite`;
- React 19 и Gravity UI (`@gravity-ui/uikit` 7.49.0);
- pdfmake 0.3.11 для отчетов PDF;
- YandexGPT или z.ai – провайдера модели выбирает администратор;
- git 2.31 или новее;
- Docker Compose и Caddy 2.10.
