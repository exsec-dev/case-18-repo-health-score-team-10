# Рекомендации

Рекомендация говорит, что сделать с репозиторием, почему и насколько это изменит оценку. Рекомендации стоят в разделе [[Рекомендации]] карточки репозитория. Чтобы сразу открыть раздел, добавьте к адресу карточки `#recommendations`: `https://health-craft.ru/repo/<org>/<repo>#recommendations`.

Рекомендации строит код по фактам анализа, без языковой модели. Как устроены правила и как считается эффект – на странице [Как строятся рекомендации](../method/recommendations.md).

## Из чего состоит рекомендация

- Номер – позиция в списке. Сначала идут критичные проблемы, например утечки секретов, затем рекомендации с наибольшим числовым эффектом.
- Действие – заголовок с глаголом, например «Добавьте файл CODEOWNERS».
- Причина – строка под действием: что не так сейчас.
- Показатель – плашка после подписи [[Показатель:]]: подметрика и ее значение, например [[label-info:CODEOWNERS – нет]]. Если подметрики нет, на плашке – [[label-info:Исходные данные]].
- Ожидаемый эффект – справа: подпись [[ожидаемый эффект]] и прирост, например [[label-unknown:+3,5 к HealthCraft Index]]. Если числа нет, эффект описан словами, например «повысит балл категории „Задачи“».

Эффект показывает, как изменится оценка, если выполнить только эту рекомендацию. Эффекты разных рекомендаций не складываются. Сумму нескольких шагов показывает режим [[По шагам]].

Рекомендации по CI/CD и Безопасности меняют Repo Health Score. У рекомендаций о файле CI эффект вида [[label-unknown:+2,0 к Repo Health Score]], число видно при доступе и к CI/CD, и к Безопасности. У остальных эффект описан словами. Их видят участники репозитория с доступом к этим данным.

## Проверить факт

Чтобы увидеть факт, на котором держится рекомендация:

1. Нажмите плашку после подписи [[Показатель:]]. Откроется окно с источником и временем сбора, например «Источник: история git · собрано …».
2. Прочитайте факт словами под источником.
3. Нажмите [[Исходные данные]]. Откроется значение факта в том виде, в каком его сохранил анализ.

Если факта нет в последнем анализе, в окне будет строка «Этих данных нет в последнем анализе».

## Режим «По шагам» {#po-shagam}

Режим [[По шагам]] показывает, как дойти до зоны «здоров»: какие рекомендации выполнить и в каком порядке. Переключатель [[По отдельности]] / [[По шагам]] появляется, если:

- HealthCraft Index ниже 70;
- в репозитории есть код;
- хотя бы 1 рекомендация поднимает индекс.

Каждый шаг пересчитан поверх предыдущих, порядок – по наибольшему приросту. Справа от шага – подпись [[после шага]] и индекс после него, в скобках – прирост шага, например [[label-unknown:65 (+3,6)]]. Как строится порядок – в разделе [Режим «По шагам»](../method/recommendations.md#po-shagam) методики.

Например, у `example/tasktracker` индекс 61:

| Шаг | Действие | После шага |
|---:|---|---|
| 1 | Добавьте в README разделы «Установка», «Сборка» и «Тесты» | 65 (+3,6) |
| 2 | Добавьте файл CODEOWNERS | 68 (+3,5) |
| 3 | Добавьте файл CONTRIBUTING.md | 72 (+3,5) |

Под шагами – итог «После шага №3 индекс – 72: зона „Здоров“». Если рекомендаций не хватает, итог называет остаток, например «После шага №2 индекс – 66, до 70 не хватит 4». Ниже, под заголовком [[Остальные рекомендации]], – рекомендации, которые в шаги не вошли.

В шаги входят только рекомендации, которые меняют HealthCraft Index, например добавить документацию или тесты. Числа шагов – расчет по текущим данным. Они не сохраняются и не попадают в отчет и публичный API. Индекс изменится только после нового анализа.

## Заготовки файлов

У рекомендаций о недостающих файлах есть заготовка: кнопка с именем файла после подписи [[Файл шаблона:]]. Заготовка собрана по фактам анализа. Имена файлов и заголовки разделов в ней те же, что ищет HealthCraft. Если выполнить шаги ниже, следующий анализ засчитает файл.

| Рекомендация | Файл | Что внутри |
|---|---|---|
| нет README | `README.md` | заголовок, разделы «Установка», «Сборка», «Тесты», «Как участвовать» |
| в README не хватает разделов | `README-sections.md` | только недостающие разделы – перенесите их в свой README |
| нет CONTRIBUTING | `CONTRIBUTING.md` | как сообщить об ошибке, предложить изменение, запустить тесты, стиль кода |
| нет CODEOWNERS | `CODEOWNERS` | владелец по умолчанию и строки для каталогов из карты владельцев |
| нет лицензии | `LICENSE` | текст MIT или Apache 2.0 на выбор |

Чтобы добавить файл по заготовке:

1. Нажмите кнопку с именем файла, например [[download:CODEOWNERS]]. Для лицензии выберите в меню [[Выберите тип лицензии]] пункт [[MIT]] или [[Apache 2.0]].
2. Положите файл в корень репозитория.
3. Замените заполнители в угловых скобках, например `<команда сборки>`. В `CODEOWNERS` замените каждый `@login` логином ответственного в SourceCraft.
4. На карточке своего репозитория нажмите [[Обновить анализ]] или дождитесь анализа по расписанию.

В `CODEOWNERS` имена авторов из git стоят подсказкой в комментариях, адреса почты туда не попадают. В лицензию MIT подставлены текущий год и имя организации из адреса репозитория.

{% note info %}

Если рекомендация уже неактуальна, заготовка не скачается. Появится уведомление «Заготовка для этого репозитория больше не нужна – обновите страницу».

{% endnote %}

## Если рекомендаций нет

Вместо списка стоит одна из фраз:

- «Рекомендаций нет – по собранным данным улучшать нечего» – все показанные категории в зоне «здоров»;
- «Автоматических рекомендаций для этих данных нет» – есть слабые категории, но правил для них нет;
- «Автоматических рекомендаций для собранных данных нет: часть данных не собрана» – слабых категорий нет, но у части категорий нет данных.
