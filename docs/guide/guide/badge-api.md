# Бейдж и публичный API

HealthCraft отдает HealthCraft Index открытого репозитория без входа: JSON для интеграций и SVG-бейдж для README. Бейдж закрытого репозитория открывается по ключу в ссылке, которую получает его участник. Закрытые данные через эти маршруты не уходят.

## Маршруты

Адреса – относительно `https://health-craft.ru`.

| Запрос | Ответ |
|---|---|
| `GET /api/v1/repos/<org>/<repo>` | JSON с индексом и баллами 4 категорий |
| `GET /api/v1/repos/<org>/<repo>/badge.svg` | бейдж с индексом |
| `GET /api/v1/repos/<org>/<repo>/badge.svg?show=rank,word,delta,cats` | бейдж с индексом и выбранными частями |
| `GET /api/v1/repos/<org>/<repo>/badge.svg?category=<категория>` | бейдж с баллом 1 категории |

Для внешних интеграций предназначен только `/api/v1`. Остальные адреса `/api/*` обслуживают интерфейс: их ответ зависит от прав зрителя и может меняться.

## Пример ответа {#primer}

Чтобы получить оценку репозитория, выполните:

```bash
curl https://health-craft.ru/api/v1/repos/<org>/<repo>
```

Ответ для выдуманного репозитория `example/tasktracker`, например:

```json
{
  "org": "example",
  "repo": "tasktracker",
  "title": "Task Tracker",
  "language": "TypeScript",
  "likes": 14,
  "healthcraftIndex": 61,
  "indexCoverage": 1,
  "categories": {
    "documentation": 47.95,
    "activity": 69.40816326530612,
    "issues": 41.5,
    "code": 79.72
  },
  "modelVersion": "4.5.0-hci",
  "scannedAt": "2026-09-20T03:14:08.512Z",
  "headSha": "4f2a9c1e7b03d58a6e91f0c2b7d4a3e8f5c6019b"
}
```

| Поле | Что значит |
|---|---|
| `org`, `repo`, `title`, `language`, `likes` | имя, название, язык и оценка реакций из каталога SourceCraft |
| `healthcraftIndex` | HealthCraft Index, целое 0-100; `null` – оценки нет |
| `indexCoverage` | полнота данных: доля веса категорий с данными, от 0 до 1 |
| `categories` | баллы Документации, Активности, Задач и Состояния кода без округления; `null` – нет данных |
| `modelVersion` | версия модели оценки |
| `scannedAt` | время завершения анализа, по которому посчитана оценка |
| `headSha` | коммит, который анализировался; `null` – коммит не определен, например анализа еще не было |

Как индекс получается из баллов категорий – в разделе [Пример расчета](../method/scores.md#primer).

Индекса нет в 2 случаях:

- данных не хватило: `healthcraftIndex` – `null`, `indexCoverage` меньше 0,4, в `categories` балл есть не больше чем у 1 категории;
- репозиторий в рейтинге, но пригодного анализа по текущей версии модели у него нет: `indexCoverage` – 0, `categories` пуст, `scannedAt` – `null`.

Repo Health Score, CI/CD и Безопасности в публичном API нет: это закрытые данные репозитория, их видят только его участники.

## Бейдж для README

Бейдж можно получить для своего репозитория с оценкой – того, что есть в разделе [[Мои репозитории]]. Чтобы получить код:

1. На карточке репозитория нажмите [[badge:Бейдж]]. Когда строке действий не хватает места, кнопка – в меню [[more:Еще действия]].
2. Выберите чипами, что показать на бейдже: у включенного чипа стоит галочка. Превью показывает результат, пока бейдж рисуется – на его месте заглушка.
3. Слева от поля с кодом выберите формат: [[Markdown]], [[HTML]], [[Ссылка]] или [[JSON API]].
4. Нажмите кнопку-иконку с подсказкой [[Скопировать]] в конце поля и вставьте код в начало README.md.

| Чип | Что добавляет |
|---|---|
| [[Лига]] | сегмент лиги: [[league-gold:TOP-10]], [[league-silver:TOP-100]] или [[league-bronze:TOP-1000]]; чип есть только у репозитория с лигой |
| [[Зона]] | зону шкалы словом: «здоров», «требует внимания» или «в зоне риска» |
| [[Тренд]] | разницу с прошлым анализом, например `+3`; после первого анализа сравнивать не с чем, и этой части нет |
| [[Категории]] | шкалы 4 категорий под индексом: Документация, Активность, Задачи и Состояние кода, у каждой балл и шкала цвета зоны; бейдж становится карточкой, а число индекса встает к правому краю |

Индекс есть на бейдже всегда. Бейдж обновляется после каждого анализа.

Формат [[JSON API]] дает адрес ответа публичного API. У закрытого репозитория этого формата нет: ключ открывает только бейдж.

Код выглядит так, картинка ведет на карточку репозитория:

```text
[![HealthCraft Index](https://health-craft.ru/api/v1/repos/<org>/<repo>/badge.svg?show=rank,delta)](https://health-craft.ru/repo/<org>/<repo>)
```

Цвет числа зависит от зоны: зеленый для 70-100, желтый для 40-69, красный для 0-39. Если оценки нет, бейдж показывает `n/a` серым, без зоны и тренда. У категории без данных вместо балла стоит `n/a`, а шкала пустая.

### Параметры бейджа {#parametry}

| Параметр | Значение |
|---|---|
| `show` | части через запятую в любом порядке: `rank` – лига, `word` – зона словом, `delta` – тренд, `cats` – шкалы категорий |
| `category` | отдельный бейдж 1 категории: `documentation`, `activity`, `issues` или `code`; вместе с `show` не указывается |
| `key` | ключ бейджа закрытого репозитория |

Каждый параметр указывается не больше 1 раза. Неизвестное значение дает ответ 400. Прежний адрес `badge.svg?style=rank` работает как `show=rank`. У репозитория без лиги часть `rank` не добавляет сегмент.

### Бейдж закрытого репозитория {#zakrytyj}

У закрытого и внутреннего репозитория код бейджа содержит параметр `key`. Ключ свой у каждого репозитория, и его видит на карточке только участник репозитория. По ключу открывается только бейдж с индексом и баллами 4 открытых категорий, без лиги и JSON. Любой, у кого есть ссылка с ключом, увидит бейдж, поэтому ставьте ее туда, где бейдж и так должен быть виден.

## Кэш и лимиты

Ответ 200 кэшируется на 5 мин (`Cache-Control: public, max-age=300`), поэтому после нового анализа бейдж еще до 5 мин может показывать прежнее число.

С 1 IP-адреса можно сделать не больше 120 запросов в минуту, лимит общий для JSON и бейджа. Сверх лимита сервис отвечает 429 с кодом `rate_limited` и заголовком `Retry-After: 60`.

Ответы `/api/v1` несут заголовок `Access-Control-Allow-Origin: *`, поэтому JSON можно запросить из браузера со страницы любого сайта, например так:

```js
const res = await fetch("https://health-craft.ru/api/v1/repos/<org>/<repo>");
const { healthcraftIndex } = await res.json();
```

Заголовок есть и у ответов 404, 400 и 429, так что браузерный код видит код ошибки. Cookie и авторизация публичному API не нужны. Не передавайте в запросе `credentials: "include"`: с ним браузер не даст прочитать ответ.

## Приватность

Приватный, внутренний, выведенный из рейтинга и несуществующий репозиторий дают одинаковый ответ 404. Бейдж закрытого репозитория с верным ключом – единственное исключение; с неверным ключом ответ тот же 404. По ответу нельзя узнать, существует ли закрытый репозиторий. В JSON и бейдже нет фактов, рекомендаций, текстов модели и данных закрытых категорий. Подробнее – на странице [Источники данных и приватность](../data/sources.md).
